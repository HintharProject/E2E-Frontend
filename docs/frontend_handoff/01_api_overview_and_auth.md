# API Overview & Authentication

## 1. Base URL & Versioning
- **Production Base URL**: `https://e2e-backend-4t9p.onrender.com`
- **Local Dev Base URL**: `http://127.0.0.1:8000` (or `http://localhost:8000`)
- **API Prefix**: All endpoints are prefixed with `/api/v1/`
- **Swagger UI**: `/api/docs/` (Interactive API playground)
- **OpenAPI Schema**: `/api/schema/`

## 2. Authentication Flow (Clerk)
The backend is completely stateless and relies on Clerk for identity.
- **Header**: All authenticated requests MUST include the `Authorization: Bearer <token>` header, where `<token>` is the Clerk session JWT.
- **Just-In-Time Provisioning**: If a user logs into the frontend for the first time, sending their first authenticated request to the backend will automatically provision their `User` record in the database based on the JWT claims.

## 3. Standard Response Formats

### Success Responses
For paginated or standard list endpoints, data is returned in a paginated JSON wrapper (as generated by DRF's default pagination or DRF Spectacular schema):
```json
{
  "count": 10,
  "next": "url-to-next-page",
  "previous": null,
  "results": [ ... ]
}
```

### Error Responses
Errors follow a strict schema separating HTTP status from business logic error codes.
```json
{
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "Invalid input provided.",
    "details": {
      "level_id": ["This field is required for students."]
    }
  }
}
```

## 4. Idempotency & Toggles
- **Toggles**: Actions like Voting, Following, or Reporting are **idempotent**. 
  - Sending `POST` twice with the same value results in a success (no-op).
  - You do NOT "toggle" by POSTing again.
  - To reverse or remove the action, you MUST send a `DELETE` request (e.g., `DELETE /api/v1/posts/{id}/vote/`).
- **Duplicate Reports**: Submitting a report against the same target twice returns a `409 Conflict`.
